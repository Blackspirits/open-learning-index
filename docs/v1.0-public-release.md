# v1.0 public release — cross-audit reconciliation

Date: **2026-09-16**

## Purpose

Close the public-site construction phase after independent review without turning the Open Learning Index into a permanently redesigned product.

Four external audit passes were compared against the repository and current generated site:

- Gemini — broad product/UX review;
- Perplexity — broad product/repository review;
- Claude Code — repository-aware technical and browser audit;
- Claude Cowork / Fable 5.1 — focused visual-design and UX audit.

The audits were treated as discrepancy detectors, not authorities. Findings were accepted only when they matched the current repository or a reproducible generated-site behaviour.

## Confirmed issues closed for v1.0

### 1. Bilingual learner-facing correctness

Some Deep Review source fields in batches 05 and 07 contained Portuguese prose even though they were projected into the English route.

PR **#152**:

- restored English source prose for the learner-facing fields of 22 affected reviews;
- preserved the pt-PT presentation through reviewed locale mappings;
- reused previously approved pt-PT wording where available;
- added regression coverage against future Portuguese leakage into English learner-facing review fields;
- stopped exposing internal recalibration/review rationale as learner-facing course copy.

Internal component-level review evidence was preserved as historical provenance when it was not part of the public learner-facing projection.

### 2. Catalogue comparison density

The previous card devoted a large 16:9 area to decorative category/provider media while hiding information needed for comparison.

PR **#153**:

- removed decorative media from catalogue cards;
- kept the provider once;
- surfaced Recommendation and Quality together;
- surfaced Quality tier;
- added a short learner-facing rationale;
- added the verification month;
- retained access, language, level and status signals;
- replaced the lock metaphor for free access with a positive availability mark;
- added controlled token-prefix search.

The public score presentation remains at one decimal place. Internal scoring precision is unchanged.

### 3. Trust and methodology on-site

The project already had a rigorous methodology, but the public site sent a sceptical visitor to GitHub Markdown to understand it.

v1.0 adds first-class EN and pt-PT methodology routes covering:

- Quality vs Recommendation;
- Quality weights;
- S+/S/A+/A tiers;
- F0/F1/F2/F3 free-access taxonomy;
- evidence standards;
- comparative admission;
- risk-based re-verification;
- editorial independence and auditability.

Homepage positioning was sharpened around the actual differentiator: independently reviewed free courses with verified access, quality and currentness. A deterministic latest-verification date replaces the weaker “100% free” statistic.

### 4. Finishing and publication hardening

The final v1.0 pass also:

- gives category pages a freshness/context note and explicit starting recommendation;
- removes redundant category tags from cards already inside that category;
- moves the mobile “Course at a glance” block ahead of long course content and hides decorative provider media there;
- shortens the final course-page tab label to reduce mobile clipping;
- replaces numbered evidence links with conservative source-type labels;
- gives the 404 page the normal site shell and stable project-root links;
- makes the Pages workflow run editorial tests and canonical-data validation before build/deploy;
- validates the new methodology routes, locale pairing and sitemap coverage.

## Findings rejected as stale or incorrect

The reconciliation deliberately rejected recommendations that did not match the current repository.

The project already had:

- JSON Schema validation;
- GitHub Actions CI/CD;
- sitemap generation;
- canonical and hreflang validation;
- one-decimal public score presentation;
- keyboard focus states;
- reduced-motion support;
- URL-synchronised filters;
- mobile-menu outside-click / Escape handling;
- course-section active-state tracking while scrolling.

The audits also contained incorrect interpretations of the F0/F1/F2 taxonomy. Those definitions were not changed.

## Decisions deliberately preserved

v1.0 does **not** add:

- a CMS or backend database;
- user accounts;
- public ratings or comments;
- behavioural analytics;
- affiliate ranking;
- a large frontend framework;
- virtual scrolling;
- scraped provider artwork;
- quota-driven feature work.

It preserves:

- the static GitHub-first architecture;
- the teal / warm-neutral visual identity;
- the light and dark themes;
- the original hero illustration;
- the SVG icon system;
- the course-detail information architecture;
- the canonical F0–F3 model;
- separate Quality and Recommendation scores;
- the public audit trail and maintenance model.

## Release boundary

**v1.0 closes the active site-construction/redesign phase.**

Future frontend changes should be driven by a demonstrated usability, accessibility, correctness or maintenance problem rather than by a desire to keep redesigning the publication.

The Open Learning Index itself remains intentionally unfinished in one sense: course access, quality, versions and alternatives continue to change. Continuous editorial maintenance remains controlled by issue **#91** and the repository maintenance policy.
