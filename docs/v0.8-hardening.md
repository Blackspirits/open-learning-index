# v0.8 trust, discovery and indexability hardening

Verified: 2026-09-14

## Decision

v0.8 closes the external audit hardening cycle without changing the project's core architecture.

The audit was treated as reproducible input, not authority. Findings that held against the repository/public build were fixed; suggestions that added product or infrastructure complexity without a demonstrated learner problem were rejected or deferred.

`data/courses.json` remains the canonical publication dataset. The public site remains static, Python-built and dependency-light.

## Delivered gates

### PR #118 — discovery, mobile and accessibility

- collapsible mobile filters;
- 24-card initial rendering with progressive **Show more**;
- combinable quick chips with explicit selected state;
- corrected Beginner-friendly semantics;
- token/word-aware search rather than raw substring matching;
- human language names;
- concise results-count live region instead of announcing the whole card grid;
- unique accessible link names and larger touch targets.

### PR #119 — learner-facing evidence

Course pages now project current editorial evidence at build time:

- prerequisites;
- required resources;
- scope;
- credential and academic-credit wording;
- component evidence;
- Recommendation rationale;
- learning need and marginal value;
- comparison context;
- identifiable evidence sources.

The official-course CTA is visible in the hero.

### PR #120 — score and trust semantics

- Recommendation is the primary learner-facing score;
- Quality remains visible as intrinsic course strength;
- the distinction is explained in the catalogue/detail experience;
- maintenance/freshness wording is learner-facing rather than internal-state jargon.

### PR #121 — static routes and indexability

- one static HTML route per public course;
- one static route per category;
- course-specific metadata and canonical URLs;
- Open Graph metadata;
- `Course` JSON-LD;
- `sitemap.xml`, `robots.txt` and `404.html`.

No frontend framework, backend or duplicate editorial datastore was introduced.

### PR #122 — reference-course calibration

The 17 pre-Phase-4 `reference_verified` courses now have a dedicated, schema-validated calibration ledger.

This avoids a false historical rewrite through synthetic Discovery/Shallow/Deep Review records while still providing the same evidence depth needed for score comparison.

Outcome:

- 17 / 17 references structured;
- 15 evidence-backed recalibrations;
- 2 score sets confirmed unchanged;
- 0 removals;
- prior components and scores preserved in the calibration ledger;
- canonical/reference-score parity enforced by CI.

See `docs/qa-reference-calibration-v0.8.md`.

### PR #123 — final reproduced QA residuals

Final QA found two remaining defects:

1. search was token-aware but the accepted curated-alias requirement had not actually been implemented;
2. the legacy dynamic `course.html?id=...` shell was still indexable and used an incomplete language-label map.

The fix adds a small curated alias layer without returning to substring search, marks the legacy shell `noindex,follow`, and uses `Intl.DisplayNames` there as well.

## Success criteria

The #117 success criteria are satisfied at repository/build level:

1. learners can see why a course is recommended and the evidence supporting it;
2. mobile browsing no longer requires traversing the full filter stack before results;
3. search is word-aware and includes curated common-topic aliases;
4. Recommendation and Quality have distinct semantics and hierarchy;
5. courses have shareable, crawlable static URLs with metadata;
6. pre-Phase-4 reference leaders are now calibrated under the current evidence/scoring model without falsifying provenance.

## Deliberate non-goals retained

v0.8 does **not** add:

- a JavaScript framework;
- backend/database/accounts;
- ratings, social features or gamification;
- provider pages without a demonstrated learner problem;
- a learning-path schema without an auditable editorial model;
- analytics by default;
- a full pt-PT interface without evidence of sufficient demand.

These remain product choices, not missing implementation.

## QA outcome

Repository validation was green on the reference-calibration and final-QA pull requests before merge.

No remaining reproduced blocker from the #117 scope is known.

The project should return to the existing maintenance tracker (#91): targeted challenger discovery, risk-based re-verification and replacement/removal when a canonical course degrades or is outcompeted.
